# 剑指美加墨（Targeting 2026）

> 世界杯结束以后，哪支球队仍是你的意难平？选中它，重新征召、排兵布阵，并亲手改写那条没有走完的路。

《剑指美加墨》是一款面向 2026 世界足球冠军赛主题的离线优先像素足球游戏。它把 23 人征召、赛程、排兵布阵、赛前道具、更衣室抉择、约 3 分钟的 11v11 直接操控比赛、战术换人、点球大战、赛后掉落与图鉴收集串成一条完整征程。

当前正式内容范围固定为 **16 支可选国家队**，不再以扩展到 48 支可玩队为交付目标。完整赛事仍保留 48 队对手数据，用于分组和淘汰赛路径。仓库从 2026-09-03 起只维护 `compliant-full` 一套合规完整产品目标；旧展示版、互动空间版与教练模式不再构建为产品入口。当前产物仍是抖音小游戏迁移前的合规 H5 基线，不能冒充已可提审的原生小游戏包。

## 为什么它不是“一次性 Demo”

完整循环是：

1. 选择国家队，从 24 人候选池中按预算征召 23 人。
2. 进入世界足球冠军赛赛程，每场重新选择阵型、首发和替补。
3. 最多携带 3 件比赛道具，并在赛前确认后锁定本场配置。
4. 在赛前、中场、加时中场和点球前处理更衣室抉择。
5. 直接操控 11v11 比赛，用战术和手动换人改变走势。
6. 赛后结算晋级、存档和道具掉落，再进入下一场。

16 支球队不是同一套数值换皮。西班牙、法国、阿根廷等强队承担夺冠压力；挪威与加拿大以突破历史为目标；佛得角追求小组出线；库拉索争取世界杯首胜。难度、阵容深度、预算、目标、技能和叙事共同构成不同的执教命题。

## 核心公平原则

- 足球运动、比分、触发和事实播报全部由本地 Runtime 决定。
- AI 不参与足球物理、比分结算或隐藏胜率；当前教练建议与赛后复盘使用本地确定性分析，断网可用。
- 数据中心、情报部门和赛后建议提供的是“可采取的行动”，不会偷偷给玩家加胜率；玩家采用推荐阵型、换人或点球方向后，才通过正式机制产生收益。
- 六类比赛道具已接入冠军征程的库存、携带、效果和掉落；不售卖直接进球、直接胜利、裁判偏置或决策概率。

## 可复现的平衡证据

项目内置 Monte Carlo 和语义审计脚本。2026-07-26 的当前基线包括：

- 16 队全对阵 72,000 场模拟，场均 6.60 次教练决策；错误阵容、是否换人和战术姿态会产生可见差异。
- 2,000 届同策略中立锦标赛，用于观察 16 队冠军分布，而不是手填“强队必夺冠”。
- 10,000 次完整征程模拟中，医疗、营养、心理和训练四类直接后勤都有正向贡献；四类全满的实验模型相对基线胜率提高 18.0 个百分点。
- 情报验证中，针对门将弱侧射门相对盲射提高约 8.8 个百分点；阵型克制建议和弱点选阵在总体样本中也为正收益。

这些数字是开发校准模型，不是对现实世界杯的预测；权威运行结果仍以正式 Runtime 和当前代码为准。

## 目录与资产约定

- `src/`：React 外壳、16 队数据、经营系统、比赛会话、决策、复盘与测试。
- `public/match-runtime-min/`：第三方物理核心与自有 HappySeed 适配层。
- `public/assets/`：合规版共用的界面、头像、聘书、事件、点球和本地音频。
- `art-packs/showcase/`：只读版权审计基线，用于校验替换素材尺寸及哈希；不会进入任何运行或发布目标。
- `art-packs/compliant/`：合规替换素材；未完整验收前保持 `pending`，构建不会回退到原图。
- `config/variants.mjs` 与 `config/art-rights.json`：唯一构建目标、功能边界和版权资源清单的来源。
- `public/pixel/`：生产像素球员、16 队球衣角色资源、装备和球场切片。
- `docs/`：游戏策划、机制算法、设计说明、验收与开发交接。
- 换设备继续开发请先看 [2026-09-14 开发交接](docs/HANDOFF_2026-09-14_DEVICE.md)；版本收敛与抖音小游戏迁移边界见 `docs/HANDOFF_2026-08-03_VARIANTS.md`。
- `scripts/`：资源生成、资产审计、包体构建与平衡模拟。

`public/match-runtime-min/scripts/match.rebuilt.js` 是第三方物理核心，不直接修改；自有适配逻辑位于 `public/match-runtime-min/standalone-match.js`、`public/match-runtime-min/happyseed/` 和 `src/services/happySeedMatchRuntime.js`。

## 发布与包体策略

```bash
npm run build
```

- 当前命令只生成 `.variant-build/compliant-full/` 网页目录，不生成旧互动空间 ZIP。
- 该目录是抖音小游戏迁移前的合规 H5 基线，不代表已经通过抖音小游戏平台构建、上传或真机审核。
- 后续平台适配需新增独立的抖音小游戏入口、生命周期、存储、触控、音频与包体流水线；不得复活旧互动空间 IIFE/ZIP 构建作为替代。
- 合规素材缺失、尺寸不符、与展示素材字节相同或最终包泄漏原图时，合规构建直接失败。
- `.variant-build/`、`.variant-public/`、`artifacts/`、旧 `dist*`、`deliverables/`、`release/` 和 `reports/` 都是本地生成物，不提交 Git。

## 当前边界

- 16 支球队技能的设计数据合同已经齐全；逐队 Runtime 效果仍需按技能做独立 A/B 验收，文档不会把展示文案冒充已经验证的隐藏加成。
- 运动饮料、冰袋、球鞋、手套、战术板和训练器材已进入冠军征程闭环，但不会购买进球、胜利、裁判倾向或决策成功率。
- 联机前端与 Node.js/Redis 房间服务已实现，包含常规、无规则乱斗和双人点球；发布前仍需部署正式 WSS 域名、配置平台白名单并完成两台抖音真机联调。
- 抖音小游戏运行环境没有浏览器 DOM/BOM；当前 React H5 必须完成 Canvas/平台 API 适配后，才可生成真实 `game.js`、`game.json`、`project.config.json` 提审包。
- 火山引擎 AI 目前不接入核心玩法。现有本地建议和复盘已经能够解释本场发生了什么，并保持断网可玩与结果可复现。

## 项目初心

我们不想做一款“换个队徽就结束”的世界杯小游戏。玩家选择的是一段真实足球语境里的遗憾：豪门为什么又差一步，黑马能不能证明上次不是偶然，新军能不能留下第一场胜利。游戏给出的不是预设答案，而是一套足够完整、足够透明的系统，让玩家用自己的名单、阵型、判断和临场选择重走来时路。

## 开源组件说明

比赛 Runtime 界面与部分基础运动、物理能力借鉴了 HappySeed 的开源组件，但本项目并未直接把原组件作为整套游戏使用。我们在其基础上对国家队数据映射、22 人 Runtime actor、像素球员与球衣、透视竖纹球场与球门球网、裁判与越位规则、战术与换人、铁血足球 HP、权威联机同步、比分统计、补时与点球、天气音效、移动端交互以及 React 业务衔接进行了大量适配和改造。历史 53 个教练决策场景仅保留为开发验收资料，不在冠军征程中触发。

HappySeed 相关能力被隔离在独立适配层中；页面、赛事、经营、存档、决策、复盘和收集系统均由本项目自行控制。因此项目对原组件的整体依赖度有限，边界清晰，也为后续替换或继续演进保留了空间。
