# 正式 Runtime：用户验收失败与返工记录

日期：2026-07-13  
状态：首轮与第二轮反馈均已进入返工；当前实现与证据以 `2026-07-14-runtime-ui-geometry-and-action-rework.md` 为准，等待产品负责人亲自验收，不等同于产品验收通过。

> 2026-07-14 纠正：撤销本文下方的 `1.104` 横向猜测校准与旧资源体积；现已使用原 Runtime `4096x2048` 几何权威层、脚底球绑定与真实骨骼动作。下方内容仅保留第二轮返工前的历史快照。

## 首轮用户验收失败项

1. 球场与观众席为脚本硬编码占位图，视觉质量不符合正式版本。
2. 事件镜头只切预设，未保证球在画面中心；正式页没有自由平移、缩放与复位能力。
3. 五个场景只绘制橙色路线标记，没有驱动真实 `pitch.ball`；点球场景缺少可辨认的球和标准点球站位。

以上失败结论撤销阶段 3、阶段 5 与正式 Runtime 首轮检查点的用户验收通过表述；旧记录仅保留为历史自动门禁记录。

## 本轮返工结果

- 参考开源 Runtime 的完整球场投影，用图像生成制作夜赛像素球场与四面人类观众席；底图按原国际球场投影做 `1.104` 横向校准。
- Runtime 合成层从 8 层硬编码装饰收敛为 4 层：ImageGen base、goal-back、goal-front、runtime-net。旧观众图集、mask、广告带、场边小人和前景栏杆不再参与渲染。
- 五个场景直接写入真实 `pitch.ball` 与渲染帧 `frame.ball`，删除橙色伪球路线标记；事件帧同时写入 `frame.camera`，保证决策出现时镜头以球为中心。
- 决策前奏停在标准开球位，选择后才播放结果轨迹：单刀带球起点、角旗区、危险任意球点、禁区带球点、点球点。
- 场景重新布置 22 人：单刀保留追防、角球双方进入禁区、任意球形成防守人墙、点球除主罚者与门将外退到禁区外。
- 正式页新增跟球、缩小、放大、复位按钮；画布支持拖动平移、滚轮缩放与双击复位。暂停等待决策时镜头操作仍立即生效。
- 默认基础倍率调整为桌面 `1.9`、小屏横屏 `1.55`，关键事件再使用独立镜头倍率。

## 浏览器复核

- 默认正式流程逐项进入：单刀 1/5、角球 2/5、危险任意球 3/5、禁区犯规风险 4/5、点球 5/5。
- 五个等待决策画面均显示真实足球；首个单刀事件修正后球位于画面中心。
- 点球复核显示球在校准后的点球区域内，门将位于球门，其他球员按规则退到禁区外。
- 连续 11v11 页面可跟随真实比赛球；暂停时缩放立即生效。
- 844×390：`document` 与 `body` 均为 `844 x 390`，无横向或纵向溢出；自由镜头按钮保持可用。
- 桌面与 844×390 控制台 error 均为 0。
