# 阶段 7：正式教练限时决策闭环

日期：2026-07-13  
状态：决策状态机自动门禁通过，但首轮用户 Runtime 验收失败；球场、真实球、事件站位和镜头已返工，暂停阶段 8 并等待第二轮用户验收。

> 纠正记录：原浏览器验收只验证流程与 DOM，没有证明球位和镜头语义正确。当前权威记录见 `2026-07-13-runtime-ui-user-rejection-and-rework.md`。

## 当前已实现

- 正式页默认从连续比赛进入“前奏事件 -> 暂停 -> 3-6 秒选择 -> 结果动画 -> 恢复比赛”。
- 首批固定接入单刀、角球、危险任意球、禁区犯规风险和点球。
- `CoachDecisionEvent` 新增正式比赛点球合同，仍使用本地成功率和本地结果解析。
- 前奏事件为零权威增量；选择后才创建唯一结果事件，Runtime Promise 完成后才结算。
- 超时自动选择最低风险方案，手动选择和超时共用一次性锁，禁止重复点击与重复结算。
- 决策直接消费当前 22 actor 的业务球员身份与原始能力数据；换人后的球员可进入后续决策。
- 决策条为底部轻量叠层，PC 三列、手机横屏横向选项，并为右下换人入口保留区域。
- `?events=auto` 保留阶段 6 五事件回归，`?events=manual` 保留连续比赛人工验收，`?lab=1` 保留阶段 2-5 实验室。

## 浏览器关闭验收

- 桌面真实 Runtime 中，首个单刀决策手动选择“打近角”，前奏阶段保持 0:0；结果动画完成后只结算一次并进入第 2/5 次决策。
- 角球决策自然超时后自动执行稳健方案；其余事件继续按危险任意球、禁区犯规风险、点球顺序运行，最终显示“5/5 教练决策”。
- 本轮混合手动/超时路径最终权威比分为 4:0，射门与射正均为 4:0、角球为 1:0，没有前奏提前结算或重复结果结算。
- 决策结束后真实执行 `#2 钢铁后卫 -> #5 边路悍将`：场上保持 11 人，换人次数从 3 降为 2；数据抽屉与换人抽屉互斥。
- 844×390 横屏页面无横向或纵向溢出。决策条右边界为 750px，换人入口左边界为 758px，保留 8px 安全间距；换人抽屉保持 11 名场上球员、12 名替补的双列布局。
- `?lab=1` 回归保持 `EVENT BRIDGE · READY`、22/22 映射、8 层/6 镜头；主菜单保持教练模式、球员模式、点球大战、设置四入口。
- 正式页、实验室与主菜单累计 0 console error，无 Vite 错误覆盖层。
