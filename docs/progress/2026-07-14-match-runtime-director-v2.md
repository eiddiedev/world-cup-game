> 历史记录：本方案已判定产品验收失败，并由 `2026-07-14-match-runtime-event-source-v3.md` 取代。V2 只保留在技术实验室，不代表当前正式 Runtime 状态。

日期：2026-07-14  
状态：53 个事件、正式 MatchScreen、2 分钟/5 决策 MatchSession 和统一播报链已完成自动门禁与桌面/844×390 整场浏览器复核，等待产品负责人亲自验收；不等同于产品验收通过。

## 本轮产品结论

上一版 Runtime 判定为产品验收失败。旧自动测试通过只能证明旧合同自洽，不能证明球场美术、球门几何、镜头、足球终点和播报时序达到产品要求。

本轮先以危险任意球锁定场内导演合同，随后按用户指示把正式链扩展到全部 53 个决策。旧 21 个正则猜测场景族和 `decisionCatalog=1` 仍不回到正式 Runtime；53 个事件改用显式场景/结果目录和当前连续比赛瞬间。

## 已完成

### 决策导演 V2

- 新增 `DecisionSceneScriptV2`，显式声明现场 22 人映射、脚下球、镜头、预览曲线、每个 outcome 的动作 cue、执行曲线、终点和时长。
- 状态机固定为 `idle -> staging -> choosing -> executing -> settled -> restoring -> idle`。
- 已移除“页面加载 450ms 后强行触发”和预制 22 人任意球站位。现在只有红队持球者在连续比赛里自然进入前场危险区域时，才按一次性本地概率生成 `runtime-decision-moment-v1`；导演直接冻结当时的球、球员和球权关系。
- 选择阶段冻结比赛时间但不冻结渲染；不切到预制镜头，只从当前跟球镜头平滑缩小 360ms 以容纳球、路线和目标区；拖动、滚轮、缩放和复位继续可用。
- 三条半透明灰色路线从当时足球位置动态生成：直接射门、传中争顶、短传重组。
- Pixi 仅绘制世界坐标路线；选择按钮改为真实 DOM 命中层，完整保留方案说明、风险、收益和成功提示。桌面/横屏越界时做最小夹取与纵向避让。
- 点击后选中路线变为金色实线，另外两条淡出；150ms 后主罚动作与足球执行。
- 释放球权时先保存原 owner，再同时释放 owner 与 ball；导演帧显式清除 `hasBall`，足球运动不再带着主罚者飞行。
- staging、执行、settled 保持和恢复改由导演自己的 `requestAnimationFrame` 时间线推进，不再依赖第三方 `setTimeout` 包装或被冻结的比赛插值帧。
- 11 个任意球 outcome 全部有显式脚本，无通用 fallback。结果播报和权威比分只在球到终点后的 `settled` 写入；终点保持 1000ms 后恢复比赛。
- 内部桥仅暴露 `prepare/execute/cancel/getSnapshot`；业务服务层的五个 V2 API 已接通。
- 开发环境支持 `acceptanceOutcome` 直达合法结果；不进入生产规则或存档。

### 2026-07-14 用户反馈修正后的复核

- 使用 `naturalDecisionChance=1` 只强制下一次合法区域窗口的概率，不写坐标。桌面实测在球的归一化位置 `[0.594, 0.486]`、横屏实测在 `[0.590, 0.332]` 等不同连续比赛瞬间自然触发，证明场景不再固定摆拍。

- 点击后 500ms 比较真实物理实体：主罚者 x/y 完全不变、`hasBall=false`、足球 owner 为 `null`，足球与主罚者距离已经拉开；修复“球员和球一起飞”。
- 选择期间 `pitch.matchTime` 保持不变；导演自己的帧时钟仍持续产生主罚动作 cue、球路、终点保持和恢复，没有再次出现 `executing` 卡死。

### 2026-07-14 正式比赛权威链与 53 事件收口

- 旧 `MatchScreen` 的独立 `setInterval` 分钟、随机比分、随机进球和独立播报已移除；正式入口直接复用 `HappySeedMatchBroadcast`，`FormalMatchSession` 成为分钟、比分、统计、播报、决策和终场报告的唯一业务权威。
- 默认现实比赛时长由 3 分钟改为 2 分钟；每场目标 5 次决策，窗口前移到 `10/24/39/54/66`，避免第三方 Runtime 在后半段状态跳转时漏掉末次事件。
- 触发器只在目标窗口之后等待当前 Runtime 球权与区域满足场景合同，不把球员和球拉到预设地点。选择阶段冻结真实比赛时间，执行结束后恢复原足球、相机和时间倍率。
- 新增 53/53 scenario 显式场景目录和 171/171 outcome 视觉终点目录。危险任意球使用专用三路线；其余 52 个场景也显式生成 `trajectory/zone/actor` 选择、动作 cue 和唯一 outcome 分支，不通过播报正则猜动作。
- 场内 DOM 按钮继续显示方案描述、风险、收益与成功提示；准备失败会取消导演并回滚决策槽位，不把整场卡在 `decision`。
- 原生 `ab-goal` 现在携带最后射门者 Runtime entity；MatchSession 按实际红/蓝比分增量解析射手，不再用进球后的开球持球者猜测，因此比分、球队和播报同源。
- 普通推进、逼抢、对抗、拦截、犯规、越位、角球、门球、界外球和手抛球违例进入同一播报时间线。手抛球违例等规则细节只播报，不打开决策。
- 正式终场报告接回 `currentRun.lastMatchResult`、比赛历史、球员体力/伤病/停赛结算和赛后页；淘汰赛 90′ 平局先进入既有本地点球大战，胜者再写入同一报告；同一 SPA 中下一场会释放旧 Runtime 启动 Promise，不复用旧终场实例。
- 桌面 `1280×720` 整场：5 次决策在 `10/24/54/61/66` 完成，比分与终场播报均为 `3:1`，按钮信息/视口/结算分钟检查全部通过。
- `844×390` 整场：5 次决策在 `10/24/41/54/66` 完成，比分、比分牌和终场播报均为 `2:0`；全部按钮在视口内，控制台 error 和失败资源请求均为 0。
- 五决策平衡模拟每组 300 场：法国/巴西的决策进球均值为 `2.58-2.77`，再与连续 Runtime 原生进球合并；弱队对强队成功率保持在 `36.73%-38.53%`。
