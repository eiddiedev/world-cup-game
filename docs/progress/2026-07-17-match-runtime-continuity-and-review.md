# Match Runtime 连贯性、真实事件与 53 项验收页（2026-07-17）

状态：自动测试、lint、build 与桌面浏览器首轮通过；仍等待产品负责人逐项验收 53 个场景，不能标记为产品验收通过。

## 2026-07-19：VAR 结论、语义高亮与导演卡死修复

- 每个真实进球继续派生同源 `var-review → var-result`，但两条事件不再挤在同一次 `200ms` 刷新：先显示“VAR 正在复核”，约 `1.1s` 后再独立送达“进球有效 / 越位无效 / 进攻犯规无效”。无效结果同时回滚 Runtime 与正式比分，并由防守方门球恢复。
- 进球无效保持小概率稳定判定；点球场景显式携带 `penalty` 事实，取消进球时只允许“进攻犯规在先”，测试禁止出现点球进球因越位被吹。
- 播报底色改为事件字段驱动：普通 VAR、普通牌、普通犯规和普通伤情使用普通底色；`detail.decision === true` 的决策过程/结果与决策进球使用高亮。球员“无法坚持”和严重疲劳继续使用高亮，但只读取 22 人 actor 的真实 `injured/stamina` 状态，`stamina <= 25` 才触发且每名球员只提醒一次。
- V3 正式导演不再引用旧版 `FORMAL_OUTCOME_VISUAL_TERMINALS`。171 个唯一 outcome 已在 V3 内逐项登记终点，场景侧继续用 override 明确本方/对方角球等上下文方向；V2 旧表只留在技术实验室。
- 修复无球路干净铲断卡在 `executing`：actor-possession 交接不再错误要求先存在足球 path，且 `duel-vector` 显式绑定执行者。干净铲断把球权交给实际抢断者；黄牌点球分支按顺序发出 `tackle-contact → penalty → card`。
- 修复多角色 motion 的 Renderer 帧错误：实体帧与渲染帧统一调用 `currentActorMotions`，删除遗留的未定义单数函数 `currentActorMotion`。浏览器清空历史日志后重跑“逼入死角”，控制台 error 为 `0`。
- 浏览器实测真实副作用：体能崩溃的“立刻换人”实际由边路悍将替下老将中卫；VAR“集体施压 / penalty_awarded”发出 `var-result → penalty`；干净铲断产生 `tackle-contact` 并正常回到 `idle`；“逼入死角”进入对方真实角球重开且不伪造射门事件。
- `844×390` 正式 Runtime 实测文档尺寸为 `844×390`、在场 actor 为 `22`、首条开球播报使用普通底色且写明“比赛正式开始”，控制台无业务 error。

## 2026-07-19：点球事实、扑救事件与中央事件层收尾

- 修复“裁判指向点球点但没有点球”的双重根因：决策后果事件现在明确区分犯规方 `side` 与获点球队 `detail.awardedSide`；真实点球即使已经用完约五次常规决策预算，也会作为同源例外进入 `penalty_kick` 闪黑重排，不再只留一条虚构播报。点球文字同步改为“比赛将进入点球处理”，只有成功创建处理链才会出现。
- 门将扑救不再只依赖“下一帧门将成为球权人”这一种情况。正式 Runtime 同时订阅原生 `Player.onBallHold` 与 `Player.onHitByBall`，覆盖接住、扑挡和随后控制三类真实扑救；每次扑救必须绑定最近的明确 `shotEventId`，同一脚射门只显示一次已有的 `扑出.png` 和同源播报。
- 比赛事件素材从左上安全区改为屏幕中央短暂接管，并扩大显示面积；素材下方增加 `Zpix` 像素大字事实标题和分钟标签，左下完整播报历史仍保留同一条事件。界面没有新增常驻卡片或第二套事实源。
- 比分牌详情触发器从会裁切子元素的比分主体中拆出，固定在比分牌左下，放大箭头并增加“查看详情”文字；展开后继续显示控球率、射门、射正、传球成功率、角球、犯规、黄牌和红牌八项数据。
- 正式页面实际使用的 `runtime-v2` 相机适配器补齐手动查看回球：拖动期间保持自由镜头，停止操作 `2.6s` 后重新调用同一跟球接口；点击“跟球”或导演恢复时会立即清除手动状态。
- 人物名牌撤销上一轮过度上移：位置回到角色头顶附近，字号改为 `13px Zpix`，头顶提示同步下移；没有改变角色世界坐标、碰撞或纸娃娃倍率。

## 2026-07-18：53 项逐选择语义执行收口

- 修复反击“拉边传中”被压成中场直接射门：该选择现在显式执行 `转移边路 → 边路传中 → 禁区接应射门` 三段足球路径，并依次发出 `pass → pass → shot` 同源事件；最终射门事件才成为进球来源。
- 所有传球 affordance 均显式声明 `targetRole`；删除通过 `cross/corner/through` 正则猜接应球员的生产逻辑。后一段球路必须从前一段接应点开始，审计发现断链即失败。
- “逼入死角”“拖延退守”“稳住站位”等非射门选择不再预演射门；只有其明确的失败进球 outcome 才生成对方实际射门分支。
- “立刻换人 / 马上换下”接入真实 `substituteRuntimeActor`：按门将资格、自然位置、当前体能选择替补，并把实际换上/换下球员写入结果反馈；失败时明确说明替补资格原因。
- 放铲选择在动作 cue 到达后发出真实 `tackle-contact`；结果合同再显式决定是否追加犯规、点球、黄牌或红牌，禁止随机纪律派生覆盖已经算出的 outcome。
- VAR、点球申诉和手球复核增加逐场景 `var-result` 合同。进球复核明确区分有效、越位无效和进攻犯规无效；点球复核明确区分判罚点球与没有点球，复核事件继续保留原始 `sourceEventId`。
- 删除新增场景使用的 outcome 正则播报 fallback。171 个唯一 outcome 全部进入显式中文语义表，VAR/手球场景另有逐场景覆写；400 个场景/选择/结果分支均不得回落到“场上局面随之更新”等无事实句子。
- 53 项验收页新增“执行顺序、运行方式、本次实际落地”，outcome 下拉在场景准备后直接显示对应中文结果；真实换人和同源裁判事件数量可在一次执行后直接核对。
- 本轮语义门禁结果：`53 scenes / 126 choices / 400 outcome branches / 70 authored paths / 171 explicit outcomes`；其中 `34` 个传球后终结分支、`162` 个规则结果分支、`6` 个真实名单副作用分支均有独立校验。

## 本轮产品反馈与处理

- 正式比赛有效时长由 2 分钟调整为 **3 分钟**；决策阅读与执行期间比赛钟冻结。
- 球门继续复用原 `stadium.json` Sprite、碰撞和动态球网。第三次现场校准按产品负责人指定方向继续向场内收拢：左门向右 `+12`、右门向左 `-12` 世界坐标；不再把 Sprite anchor 误当门柱坐标。
- 半场重新落位改为带“半场 · 45′”说明的短转场，消除无原因黑屏的观感；定位球闪黑仍只能由带正确来源方的真实犯规、角球、界外球或点球事件触发。
- outcome 执行路径继承玩家所选预览路径，不再重新生成一条通用弧线；结果终点可接管球权时调用 Runtime 原生 `forceTrap/trap`，从 outcome 终点继续比赛。
- 所有射门 choice 固定为 `ball-only-shot`：执行时解除持球，只移动足球；即使该 choice 同时声明跑位提示，也不得生成 actor motion 或 carry path。
- Runtime moment 现在从两边门将实时位置推导 `attackDirection`，上下半场自动镜像。30 个实时机会触发器统一使用进攻进度、事件类型和有效区域；门将清道夫额外要求足球已进入本方身后危险区、门将离开门线且接近足球。
- 正式事件链开始统计真实 `shot/save/corner`，并由真实 `tackle-contact` 派生带 `sourceEventId` 的犯规、牌、伤病和禁区点球；手球、VAR、越位和手抛球违例也必须保留真实来源事件。
- 角球、本方进入进攻禁区、对方进入本方禁区改为事件优先触发，不再与 53 场景通用池随机竞争：本方角球固定进入前点/后点/战术角球，本方禁区机会进入传球/射门选择，对方禁区机会进入逼抢/铲球选择。自然机会不必等待固定分钟，单场上限仍为 5 次。
- 犯规派生事件已接回同一音效总线：真实接触播放铲球声，派生犯规/牌播放双段哨声，真实扑救播放独立扑救声；比赛背景音乐默认增益由 `0.035` 降至 `0.018`。
- 复用已有 `比赛事件` 图片，在真实角球、扑救、进球、黄牌和红牌时短暂浮现在草坪左侧；不新增卡片墙，也不复制二进制资源。
- 独立 Runtime 在浏览器尚未授权声音时增加一次“点击开赛”门禁：音频样本先预加载，用户手势先解锁 AudioContext，再启动比赛，因此比赛不会先静音跑一段时间。由主菜单进入且音频已经解锁时不重复显示。
- `pass` 与普通触球共用本地触球采样；铲球按产品反馈改为同一触球采样。门柱/横梁继续使用独立金属碰撞声，并在 Runtime 事件层增加 `420ms` 碰撞去重。
- 修复防守角球主罚方：对方角球的 `setPieceTaker` 和足球来源 actor 必须为蓝方，本方 `primary` 只承担盯人与区域防守，不再被放到角旗区。
- 射门执行增加双重不变量：强制解除 `ball.owner`，并在实体帧与渲染帧同时锁定 `ball-only-shot` 射手原位置；畸形 actor motion 也不能带动射手随球飞行。
- 半场转场明确显示“上半场结束 · 45′”并保持可读时长；`HalfEnded` 在全场结束时不再错误进入 `ChangeSides`，因此终场不会闪黑后重新开球。播报改为明确的半场/终场文案，不再显示笼统的“比赛阶段发生变化”。
- 修复三分钟比赛的旧分钟换算系数：Runtime `2700/5400` tick 现在分别严格映射为 `45′/90′`，`period-change` 事件也显式携带 `45/90`，不会再在记分牌约 `22′` 时显示半场。
- 相机默认持续跟随足球；手动拖动画布只做临时查看，停止操作 `2.6s` 后自动平滑归还跟球。人工缩放只改变倍率，不再永久关闭跟球；决策摆入与恢复也继续以真实足球为相机目标。
- 铲球纪律拆成真实动作判定：门将完全不进入 `tackle-contact`，同队接触不进入放铲链；`slide-trap` 明确为先触球，`slide-hit` 明确为未触球。禁区内 `slide-hit + missedBall` 必定派生犯规和点球，普通争抢不再按动作外观猜牌。
- 纪律概率只在已经判犯规后运行：出牌阈值提高，直接红牌约占犯规 `2%`；黄牌按 `runtimeActorId` 累计到角色状态，球员名字左侧显示黄牌标识，第二张黄牌同时计黄/红并通过 Runtime `removePlayer` 罚下。
- 射门限制从 choice 级扩展到 outcome 级：任何有真实球路且终点为进球或门将的分支，都强制 `ball-only-shot`、解除持球并禁止 actor motion；人员、VAR、裁判和阵型选择继续保持无足球路径。
- 新增独立入口 `happyseed-decision-review.html`：53 项全部使用中文触发说明，并显示完整选项说明、风险、收益、六类场内表达和开发环境 outcome 直达。
- 决策进球改为单一比分权威：本地 outcome 只登记“等待真实门线确认”，只有 Runtime `goal` 才写比分；同一 `shotEventId` 在 `2.5s` 内重复进入门线会在事件源撤销原生重复分数，不再重复发出进球、音效、图片或播报；MatchSession 仍保留第二层幂等防线。
- `ball-only-shot` 执行器的球权释放拆成可重复、逐项容错的操作；每帧继续锁定射手实体与渲染位置，但 `ball.owner` 的只读/异常赋值不再中断导演时间线。导演 `tick` 发生异常时会安全取消并恢复，不能永久停在 executing。
- 门将单刀和清道夫场景的主角明确绑定本方门将，不再把最近的中卫插入门将文案。单刀守门分支显式包含“对方射门 → 门将起跳 → 双手控制球”，结果播报只在该动作到达终点后出现。
- 场内路线改为 4px 网格采样的像素虚线；默认低亮灰、hover 高亮米黄、选中实色金黄，HTML 选项按钮和草坪路线共用同一 hover 状态。
- outcome 播报开始区分射门与传球：传中/直塞导致的进球会补接应球员攻门 cue，不再把所有到达球门的路径都播成主罚者直接射门；门将控制传中与门将扑出射门也使用不同事实文案。
- 首次中圈开球播报固定为“比赛正式开始”，只有进球、半场后的后续开球才使用“比赛继续”。
- 独立验收页保留用户在“摆入场景”前选择的 choice/outcome，不再在准备完成后偷偷重置成第一个选项。
- 点球申诉、禁区手球与门线手球复核新增禁区事实门禁：真实 `shot` 事件记录进攻方向和当帧球位是否处于进攻禁区，派生事件沿用同一字段；禁区外事件不得进入这三类点球/手球 VAR 决策。
- 门框碰撞改为双来源但单次结算：优先订阅上游 `Goal.onPostHit/onCrossbarHit` 权威碰撞信号，网络帧 `eventName` 继续作为兜底，两条来源共用 `420ms` 去重和同一个 `shotEventId`。先播放门柱/横梁声，随后若真实越过门线再由 `goal` 事件播放入网与欢呼。
- 半场和全场的 `period-change` 统一播放“一长一短”裁判哨；全场由 `EndMatch` 单点发出，`HalfEnded` 不再重复发终场事件或重新开球。
- 带球后射门不再把角色和足球绑定到同一终点：导演明确拆成 `carry-then-shot` 两阶段，前 `1080ms` 用循环跑动动画和脚前交替触球推进，随后解除球权并只让足球沿射门路径飞行，球员停在起脚点。
- 决策执行不再把其余 21 人全部钉死：排除主角、门将和明确脚本参与者后，选取临近的 6 名场上球员做小幅接应/回防跑动，并在 outcome 结束时自然归位；不会改变权威球权或结算位置。
- 53 项 V3 几何改为绝对主客队合同：126 个选择中的每条 `ball-path` 都显式登记 `home/away` 和执行角色，每条 `run-lane` 都显式登记跑动角色；`goal-for` 永远指向本方进攻球门，`goal-against` 永远指向本方防守球门，不再把当前进攻方向误当成比分方向。
- 修复角球方向反转：定位球合同切换主罚方时同步镜像 `attackDirection`；12 个闪黑场景统一把真实主罚者锚在同一个足球位置。对方角球、对方任意球的人墙、接应者和主罚者均按对方进攻方向布置，准备与执行不再跨到另一侧角旗区。
- 定位球重排后重新计算所有 actor 动态锚点，近点、远点、短角球接应点和人墙不再继续使用黑场前的旧坐标；独立验收页也不再提前篡改采样瞬间的 `attackingSide`。
- 门将出击改为统一拦截点：门将跑动线与足球结果线在球路约 `46%` 处相交，成功分支只有在 `pitch.ball.owner` 确认为该门将后才能进入 `settled`。结果画面保持完整 `800ms`，期间比赛钟和球权仍冻结，播报结束后才恢复连续比赛。
- 传中、角球、直塞等“传球后射门”结果不再把开球者记成射手：释放时先发真实 `pass`，接应球员起脚 cue 到达后再发第二条真实 `shot`，进球仍由最终门线事件确认。
- 射门预览不等于射门已经发生：犯规、拖延成功等 `hold` 结果不再沿预览射门线移动足球，也不播放射门动作，避免播报与画面相互矛盾。
- 新增 `audit:decision-scenes`，逐项打印并校验 53 场景、126 个选择、400 个结果分支和 75 条显式场内路径；验收页中的 `{player}` / `{opponent}` 占位符同时改为可读中文名称。
- 独立验收页连续重开 Runtime 时，场景采样优先读取当前球场的 22 人实体绑定，不再只依赖上一轮 `runtimeEntityId`；因此逐项切换场景不会误报“22 人和足球还没有进入可采样状态”。
- 决策射门的角色锁定从易失的实体 ID 扩展为 `side + runtimeLocalIndex` 的当前帧精确绑定；单刀近角和挑射执行时射手停在起脚点，只有足球沿球路进入球门。
- 决策进球新增门线终点提交：只有足球实际到达显式 goal path 终点，才按同一 `shotEventId` 单次发出 `goal`、比分、播报、图片和音效；越线但无事件以及结果播报与比分脱节都被拒绝。
