## 本轮验收边界

先收口正式 `happyseed-runtime.html` 的比赛 Runtime 界面：球场与看台美术、旧 Runtime 几何、事件镜头、自由镜头、五次正式决策的脚下球和可见骨骼动作。在这些基础通过后，只扩展现有 53 个本地决策到同一事件桥；没有新增联网依赖，也没有进入阶段 8 的全量规则 UI。

## 已完成

### 球场与观众席

- 新增 `stadium-environment-v2.png`，使用图像生成的最高可用输出质量制作夜场人类观众与看台；生成层只负责场外环境，不再决定比赛线条。
- 旧国际球场 `4096x2048` 源图成为草坪几何权威；原边线、半场线、中圈、禁区、六码区与球门线在固定遮罩内直接复用。
- 源图比赛区锁定为 `x=648, y=611, width=2800, height=1057`；`baseTexture` 实测为 `4096x2048`，外层显示合同为 `5120x2560 / 1.25`。
- 删除被否定的 `2048x1024` 模糊底图与 `1.104` 横向猜测校准。球门前后框继续使用原 `stadium.json` 坐标与原 goal atlas，球网、碰撞和深度排序仍归 Runtime。

### 镜头

- 决策铺垫先切到真实球/持球人位置，结果阶段逐帧跟球。
- 画布拖动后镜头进入 `free`；事件桥检测到自由模式后不再在下一帧抢回镜头。
- 跟球、缩小、放大、复位、拖动、滚轮与双击复位继续可用。

### 五个正式决策演出

- 铺垫阶段球使用当前真实持球角色的 `root-footline` 锚点；五个正式场景浏览器实测球—脚世界距离均为 `0`。禁区防守场景的持球者已纠正为对手前锋，不再把球错误放到我方后卫脚下。
- 结果前 18% 保持球在脚下，之后才进入连续球路，避免按钮刚按下球已经飞走。
- 骨骼动作时间线已接入：主罚者 `shoot`、门将 `jump`、扑出后的 `hands_in_front`、任意球人墙 `jump`、角球接应者 `jump`、犯规防守者 `slide` 与进攻者 `fall_forward`。
- 正式点球扑救浏览器实测记录为 `primary=shoot`、`goalkeeper=jump`、`goalkeeperClaim=hands_in_front_back`，球在扑救镜头内到达门将区域。
- 单刀防守不再复用门将开球球路：由对手前锋持球逼近，扑救成功后球权转绑门将；浏览器同时捕捉到 `primary=hands_in_front`、0:0 比分和“门将完成扑救并控制住皮球”的本地播报。

### 53 个本地决策 Runtime 桥

- `decisionLibrary` 的 53 个场景全部输出完整 `CoachDecisionEvent`；不再有 47 个场景因注册表缺失而返回 `null`。
- 23 个既有动画标签被归并为 21 个稳定场景族，覆盖常规进攻、反击、远射、直塞、点球、门将、最后防线、中场争夺、角球攻防、越位线、换人、VAR、任意球防守与禁区混战。
- 每个场景族都声明球权角色、目标角色、连续球路、镜头预设、站位模板与结果动作；防守场景不再假定 `primary` 永远持球。
- 171 个本地可能结果均有无网络播报 fallback；保留 6 个精修代表场景的专用文案，其余场景使用结果语义模板。
- 修复门将单刀失球的比分权威缺口：`goal_chip_over`、`goal_corner`、`goal_tight_angle`、`goal_zone_gap` 与 `counter_equalizer` 现在正确计入对手比分。
- 默认正式比赛仍只播放 5 个代表决策，避免把 53 次选择塞进一场比赛；完整目录通过独立验收参数逐项直达。

### 直接验收入口

- 默认完整流程：`/happyseed-runtime.html?mode=coach`
- 连续 11v11：`/happyseed-runtime.html?mode=coach&decisions=off&events=manual`
- 任意正式决策直达：在默认入口追加 `decisionStart=0..4`，依次对应单刀、角球、危险任意球、禁区犯规风险、点球。默认不带参数时行为不变。
- 53 场景验收目录：`/happyseed-runtime.html?mode=coach&decisionCatalog=1&decisionStart=0`，将末尾数字改为 `0..52` 可直达任意本地决策。
